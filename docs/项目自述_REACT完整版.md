# 一个面向企业 IT 运维的"网络安全管理 AI 助手"是怎么来的——项目完整自述

> 这篇文章我不堆术语、不包装，按自己真实的决策顺序写：**先讲清楚为什么做（Reason）→ 再一个个挑技术（Explore）→ 然后动手、踩坑、填坑（Action）→ 最后用真实数字检查结果（Check）→ 并诚实反思局限（Think）**，正好是 **REACT** 五段。
>
> 每个名词我都会解释一遍，哪怕你完全不懂网络安全也能跟上。所有数字都来自我本地真实跑出来的结果文件，不是编的；有些数字"不好看"，我也照写并解释它意味着什么。

## 先用一句话说清楚

这是我在**香港科技大学"信息与网络安全管理"专业就读期间（2025 年 8 月 — 2026 年 11 月）做的研究型项目**：一个**装在 Windows 上、面向企业 IT 网络运维人员的"网络安全管理 AI 助手"**。

它解决的核心场景很具体：一线运维工程师在日常工作中拿到一段网络抓包文件（`.pcap`，可以理解成"网络的行车记录仪"），想快速搞清楚——

1. **这里面有没有攻击 / 异常？是什么类型？严重吗？**（多引擎检测）
2. **凭什么这么判断？证据在哪？能不能出一份可以存档、上报的报告？**（取证报告）
3. **我不是安全专家，这些术语看不懂，能不能用人话解释、让我追问，并告诉我下一步该怎么处置？**（AI 助手）

它是**双击图标打开的独立桌面软件**（不是网页）。核心检测**不联网、不花钱、不需要账号**就能跑；只有"AI 写研判、回答安全问题"这部分需要用户自己配一个大模型 Key。

下面从头讲。

# R — Reason：我为什么要做这个系统（从背景和目的倒推）

## R1. 开发背景：它源于我在港科大的研究方向

2025 年 8 月，我进入香港科技大学攻读**信息与网络安全管理（Information and Network Security Management）**。在学习和研究过程中，我反复接触到同一个现实问题：

**网络安全的"最后一公里"，往往落在一线 IT 运维人员身上，但他们手里缺好用的工具。**

具体来说：
- 大企业有专门的安全运营中心（SOC）和安全分析师，但**大量中小企业、机构的 IT 部门，运维和安全是同一拨人**——他们要保障网络和业务正常运行，却未必受过系统的安全训练。
- 真遇到可疑情况（网络变慢、主机异常、怀疑中招），他们的典型动作是抓一份网络流量包，然后**要么凭经验肉眼排查（非常耗时、容易漏），要么只能花钱等外部安全厂商**。
- 通用的安全工具要么太"重"、太专业（一堆告警和术语，运维看不懂），要么是实时部署的大型系统，不适合"拿到一个文件快速看一眼"的场景。

于是我的研究方向逐渐清晰：**能不能做一个轻量、开箱即用的 AI 助手，把"专业安全分析师看包、研判、写报告"的能力，下沉给每一个普通运维人员？** 这正是这个项目的初衷——不是为了炫技，而是瞄准一个真实存在、又和我专业高度相关的需求。

## R2. 我给自己定的目的和约束

这个项目要同时服务于"研究"和"落地"，我把目的和约束摆得很明确：

- **它得是一个真能用的工具**，对应运维人员真实的工作流，而不是一个只能演示的玩具；
- **它要能体现"AI + 安全"的结合**，并能作为我求职腾讯 / 字节 / 阿里"AI 全栈开发 / AI 网络安全"岗位的代表作，经得起面试官追问"为什么这么做、数字怎么来的、换数据还行不行"；
- **不能把用户电脑拖垮**——运维人员的机器往往还要跑别的系统，工具必须轻；
- **要方便迁移和部署**，最好做成一键安装，普通运维不装 Python、不配置环境也能用；
- **不脑测、不编数据**，任何指标都要能在本地重跑出来。

## R3. 关键的一次"做减法"：为什么聚焦"离线 PCAP 分析"

"安全 AI 助手"可以做很多功能，我做了一次很重要的取舍，把范围收敛到**离线 PCAP 分析**这一个核心切口。我逐个否掉了看起来更酷的方向：

- **为什么不做"实时防火墙 / 入侵防御（IPS）"？**
  实时防护要在真实网络链路上毫秒级拦流量，涉及网卡、驱动、高并发，误拦了正常业务还要担责——这是大厂一个团队长期打磨才敢上线的东西，个人做要么做不深、要么不敢真用，对"帮运维快速看包"这个目标也没有直接帮助。

- **为什么不做"在线 SaaS、多用户、上云"？**
  那会引入账号、服务器成本、数据库运维、多租户隔离，工作量全花在和"安全分析"无关的地方，还和"轻量、可迁移、不拖垮机器"的约束冲突。

- **为什么最终选"离线 PCAP 分析 + AI 助手"？**
  因为它**正好是运维 / 安全人员最常见的工作姿势**：出问题后抓一个包，事后离线地、反复地看——攻击什么时候开始、干了什么、影响多大、要拉黑什么、怎么补救。这叫**数字取证（Forensics）**。
  这个场景对我也友好：
  - **可复现**：同一个包，今天分析和明天分析结果一致，方便测试、方便写进自动化；
  - **不依赖特殊硬件、不碰别人网络**，一台普通电脑、分析一个文件即可，合规又安全；
  - **天然适合 AI**：人工读包、写报告要几小时，正是大模型能帮运维提速的地方。

> **用"如果不这样会怎样"检验**：如果贪多做实时 + 云端，我会被驱动、性能、运维拖住，没有一块做得深，一追问就穿帮。把"离线分析 + 取证 + AI 研判问答"做扎实，反而更可信。**项目比的不是功能数量，而是深度和真实度。**

## R4. 目的决定的几条"铁律"

1. **API Key 绝不写死在代码里**——那是用户个人凭证，写死既不安全也不专业；
2. **核心检测必须能离线运行**，不把"没网 / 没 Key"的用户挡在门外；
3. **能一键安装、整体可迁移**；
4. **AI 只做"助手"该做的事**：检测结论由确定性引擎给出，AI 负责解释、研判、答疑、给处置建议，不允许它凭空编一个"有没有攻击"的结论。

# E — Explore：技术是怎么一个个选出来的

我不是先列"我要用这些技术"，而是顺着**数据在系统里怎么流动**来选：

```
PCAP 文件 → ① 解析数据包 → ② 把零散的包还原成"网络流"
→ ③ 多个检测引擎分别判断 → ④ 融合结论
→ ⑤ AI 研判 / 问答 / 给处置建议 → ⑥ 生成取证报告 → ⑦ 桌面界面展示
```

## E0. 语言：Python

安全 + 数据 + AI 领域 Python 生态最全：解析有 scapy、机器学习有 scikit-learn、大模型有成熟 SDK、打包有 PyInstaller。语言是被"要做的事"选出来的。

## E1. 解析与流重组：scapy

`scapy` 是 Python 解析网络数据包的事实标准，能从以太网、IP、TCP、UDP、DNS 一层层拆字段。

**什么是"网络流（Flow）"？** 抓包里是成千上万个零散单包，光看单包没意义。"流"是一次完整通信，比如"我电脑 12345 端口 ↔ 某服务器 80 端口之间的所有包"。把它们归到一起，才能看出这次通信传了多少、什么协议、正不正常，这叫**流重组**。

## E2. 检测引擎：为什么要"多个引擎"

没有任何一种检测方法是万能的。打个比方，判断一个人可不可疑：可以照章办事（规则）；可以记住他平时作息再看反常（基线）；可以综合几十个维度找出"格格不入的人"（无监督）；也可以给他看大量标注好的好坏样本学会分辨（监督学习）。它们各有盲区，所以我都做了再融合。

### 引擎①：规则引擎（专家经验）
把已知攻击特征写成规则：大量 SYN 包完不成握手 → SYN 洪水；一台主机短时间扫很多端口 → 端口扫描；DNS 查询名又长又随机、频率高 → DNS 隧道（把数据藏在 DNS 里外传）。
**优点**：可解释、零训练。**短板**：只认已知模式，且阈值靠人**拍脑袋**定（"我觉得 100 个算攻击吧"），换环境就误报 / 漏报。后面的基线和监督模型，本质就是解决"拍脑袋"。

### 引擎②：时序基线（学习"什么是正常"）
先看一段确认正常的流量，用**中位数 + MAD**（这两个统计量抗污染，少量异常不会把它们带偏）统计正常范围，再用"偏离几个标准差（σ）"判断异常；并保留 EWMA 做在线更新。
我还做了**多维度联合检测**（字节、包数、连接数、速率一起看）和 **STL 分解高级模式**（把"趋势 + 每天的周期高峰 + 残差"拆开，避免把每天下午的正常高峰误报）。
**价值**：阈值不再拍脑袋，而是从用户自己环境的正常流量里学出来。

### 引擎③：孤立森林（无监督）
不需要好坏标签，"很容易被随机切分单独挑出来的样本就是异常"。作为多维异常的补充，短板是结果不太好解释、召回有限。

### 引擎④：监督模型（主引擎）：HistGradientBoosting
用大量标好"正常 / 各类攻击"的流样本训练 `HistGradientBoosting`（scikit-learn 自带的直方图梯度提升树），它**召回最高、当主力**。
**为什么不用更时髦的深度学习？** 网络流是典型表格数据，梯度提升树在表格数据上长期比多数神经网络强、训练快；而且它是 sklearn **自带、零额外依赖、打包小**，直接服务"轻量、可迁移"。为防**过拟合**（只会背训练答案、换数据就不行），我做了 L2 正则、早停、5 折交叉验证。

### 融合：级联 + Stacking
多引擎结论怎么合？拍脑袋加权不可靠，我最终用 **Stacking（元学习器自动学习"该更信哪个引擎"）+ 级联（便宜高召回引擎先过滤、拿不准的再交给重模型）**，兼顾效果和算力。

## E3. AI 助手：大模型、RAG、防幻觉

### 大模型：glm-4.5-air，兼容多家
默认用智谱 **`glm-4.5-air`**（OpenAI 兼容协议、快、中文好、性价比高），并做成**兼容 DeepSeek / OpenAI / 本地 Ollama**，用户在设置里改地址和模型即可。Key 在 Windows 上可用 **DPAPI 加密存储**（系统级加密，只有当前用户能解）；开箱也支持写在本地 `.env`（该文件不入库、不打包），不写死、不明文分发。

### 本地嵌入：BGE-small-zh（ONNX，完全离线）
要让 AI"查资料"，先把文档转成语义向量（**Embedding**），语义近的向量也近。我用 **`BAAI/bge-small-zh-v1.5` 的 ONNX 版**：本地、免费、不要 Key、中文好、依赖轻。

### RAG（检索增强）：为什么必须有
通用大模型不知道"你这份报告里有什么"，还可能把协议号、攻击编号记错（**幻觉**）。RAG 的做法是：我把网络协议、网络安全、MITRE ATT&CK（全球通用攻击技术库，每种技术有编号如 T1046）等资料做成可检索知识库；提问时**先检索真实资料、连同问题一起给模型，让它"看着资料回答"**。用 **ChromaDB（语义）+ BM25（关键词，查编号更准）混合检索 + 轻量重排**，且都是本地文件、零独立服务。

### 防幻觉：具体怎么落地（面试必问）
1. **强制引用来源**，检索不到就明说"知识库没有"，不硬编；
2. **输出校验器**：核对协议号、技术编号是否与资料一致；
3. **置信度交叉验证**：关键结论用不同温度多次采样，分歧大就标注"需人工确认"；
4. **复核标记**：AI 内容统一标注"AI 辅助、需人工复核"。

**一个真实纠正例子**：问"T1046 是什么？"——**直接问模型答错了**（说成"网络共享驱动、初始访问"），**走 RAG 后答对**（"网络服务扫描、侦察"）。这证明 RAG + 校验真的在拦幻觉。

## E4. 后端、界面、存储、打包
- **FastAPI**：把能力做成本地接口，带 **Token 鉴权**和**审计日志**（记录谁何时做了什么），这是安全系统的基本素养；
- **pywebview 独立窗口**：用户要的是"双击图标弹独立软件"，不是浏览器标签。pywebview 调用 Windows 自带的 **WebView2** 渲染，轻且像原生；Gradio 快速搭分析界面，我再用**自定义 HTML/CSS** 调成蓝色、二次元风格；
- **存储**：SQLite + ChromaDB，都是本地文件、无需独立数据库服务，整个文件夹拷走即可迁移；
- **打包**：PyInstaller 打成可执行程序，Inno Setup 做成 Windows 安装程序（快捷方式、卸载、可选填 Key、自动装 WebView2）。

# A — Action：怎么一步步做的，以及真实踩过的坑

## A1. 先有"最小闭环"，再长肉
第一步只跑通一条线：一个包 → 解析 → 几条流 → 最简单规则判断 → 页面能看到。端到端通了，确认骨架成立，之后基线、ML、RAG、报告、桌面化、安装包都是往上加，每加一块就回归测试。

## A2. 数据从哪来：面对"拿不到企业真实数据"的现实
我不可能拿到企业真实流量（机密），于是用四类数据分工：

| 数据 | 是什么 | 用途 |
|---|---|---|
| **UNSW-NB15** | 新南威尔士大学现代攻击数据集，约 17.5 万条流、9 类攻击、特征全 | **主力**：训练 + 评测 |
| **NSL-KDD** | 经典数据集改进版 | **跨数据集压力测试**：换个数据还灵不灵 |
| **UNSW-CIC 重提取版** | 把 UNSW-NB15 底层流量用 CICFlowMeter 重新提取的 76 维版本，约 44.8 万流（**非公开 CIC-IDS2017**） | 第二特征体系，验证 76 维 CICFlowMeter 特征 |
| **自建 golden 小样本** | 脚本生成的 10 个小 pcap | 单元测试 / CI，秒级重跑 |
| **真实恶意样本** | 真实 Lumma 信息窃取木马感染流量 + 官方 IOC | 证明在真实（非教科书）流量上能跑、结论能对上官方指标 |

**诚实说明局限**：UNSW 这类数据集的 CSV **没有逐条真实时间戳**、做了**匿名化**（无真实 IP/端口/内容），导致 SYN 洪水、端口扫描、DNS 隧道这类规则在上面**没法直接测**。不过官方把数据切成了**两个不同采集时间窗**的 training-set / testing-set，我据此做了**时间外推（OOT）评测**：用早期时间窗训练、晚期时间窗测试，F1=0.8924（比同分布 0.9704 低约 0.086），比单纯分层随机更接近"用过去预测未来"。即便如此，公开数据集 ≠ 生产流量，这正是我还要做跨数据集迁移评测 + 真实样本补位的原因。

## A3. 真实踩过的坑（现象 → 根因 → 修法）
1. **实际跑的后端"裸奔"**：重构后同时存在两个 FastAPI，被运行的是缺鉴权 / 审计的残缺版。**修**：让 main 只 re-export 唯一完整 app。
2. **同一包反复分析生成一堆报告**：原来用"文件路径 md5"当标识，换目录就当新文件。**修**：改用"**文件内容 SHA-256**"，实现一个包 ↔ 一份报告、重复分析只覆盖。
3. **Stacking 接口没写全，空输入崩溃**：补全，并在无元学习器时自动回退加权。
4. **启动引导弹窗打包后不显示还卡死**：windowed 模式下 tkinter 弹窗不渲染又阻塞。**修**：删约 200 行启动前引导，改成应用内引导。
5. **整个界面 404**：新版 Gradio 下拉框不支持某参数，一个组件报错拖垮整页。**修**：移除该参数。
6. **点一下开两个报告**：两个标签页按钮同名变量被覆盖、绑了两个事件。**修**：改名、事件分离。
7. **知识库加载慢、卡 50%**：精简加载逻辑、给出明确状态。
8. **"下载报告"没真正进下载栏**：改成按钮下显示进度、完成后弹"是否打开"、提供"打开所在文件夹"。
9. **精简系统缺 WebView2 软件打不开（v3.0.1）**：安装程序注册表检测，缺失先弹窗，点安装后自动运行内置的**微软官方在线安装器**（已校验 Authenticode 签名）静默联网安装，处理成功 / 需重启(3010) / 已存在(1638)，非提权不弹 UAC。

> 共同规律：很多坑在"源码能跑"时根本不出现，只在打包、换环境、升级依赖时暴露。所以我坚持在最终交付形态下验证。

## A4. 测试与 CI
- **148 个测试（19 个按环境条件跳过）**覆盖解析、各引擎、融合、RAG、报告、API、存储；
- v3.0.0 接手时是 **11 失败 + 1 错误**，我逐条找根因修复、**全程没放宽断言**（改松标准让测试变绿没有意义）；
- **GitHub Actions（CI）**：推送后云端自动装依赖、跑测试、验证打包，不依赖我这台机器。

# C — Check：最终结果，用真实数字说话

## C1. 系统组成与功能
- **桌面应用（pywebview 独立窗口，蓝色二次元风格）**；
- **PCAP 分析页**：拖入包 → 多引擎检测 → 流量概览 / 完整 JSON / AI 威胁分析，可下载取证报告；
- **分析历史页**：列出每次分析的文件、详情、时间（格式 `2026/9/8 23:20`）、报告；"打开报告"先找该记录对应报告，找不到就问是否后台重新分析（不影响分析页）；
- **基线管理页**：上传正常包 → 一键学习 → 命名保存 → 列表 / 删除、查看基线图；
- **知识库管理 + 安全问答页**：查看 / 初始化知识库，向 AI 提问（回车提交），回答带出处、保留对话历史；
- **后端 FastAPI**：本地接口、Token 鉴权、审计日志。

## C2. 核心指标（真实，附结果文件）
**监督模型 UNSW-NB15（train 14 万 / test 3.5 万，194 特征）**：
- Precision **0.9637** / Recall **0.9772** / F1 **0.9704** / Accuracy **0.9594**
- 过拟合：训练 F1 0.9791 vs 测试 0.9704，**gap 0.0088，风险低**；5 折 CV **0.9394 ± 0.0429**
- 时间外推 OOT（早期时间窗训练 / 晚期时间窗测试，82,332 流）：Precision **0.8187** / Recall **0.9808** / F1 **0.8924**，较同分布衰减 **0.086**

**各引擎召回对比（说明为什么需要监督模型）**：规则 0.0001 / 基线(σ=2) 0.5045 / 孤立森林 0.2107 / **监督 0.9772**

**RAG 黄金问答（16 题，双口径）**：
- 严格口径（必须命中唯一正确条目）：Recall@1 **0.6875** / Recall@3 **1.0** / Recall@5 **1.0** / MRR **0.8333**
- 相关口径（命中同主题相关条目即算）：Recall@1 **0.875** / Recall@3 **1.0** / Recall@5 **1.0** / MRR **0.9375**
（Recall@5=1.0 即每个问题的正确资料 100% 出现在前 5 条里；两个首位瑕疵为 T1021、T1082，正确条目都在前 3）

**融合架构 held-out F1**：固定权重 0.958（弱引擎稀释、最低）→ Grid Search / Stacking / 级联 均 **0.969**（自动把权重集中到监督模型）

**性能**：典型 <3000 包文件 **0.03–2.7 秒**、内存峰值 **<8.2MB**；10 样本平均 4.22s / 23MB——对"不拖垮机器"达标。极端高基数文件（1.1 万短连接）22s / 124MB，属已知瓶颈。

**工程**：148 测试通过 / 0 失败（19 个按环境条件跳过）；版本 **v3.1.1**；安装包内置依赖、模型、WebView2 安装器。

## C3. 我把"不好看"的数字也摆出来
1. **跨域迁移 F1 仅 0.192**：把 UNSW 训练的模型直接用到 NSL（两数据集语义可对应的 5 个共有特征），F1 从同分布的 0.964 暴跌到 0.192，**域偏移鸿沟 Δ=0.604**。这说明没有"一个模型走天下"，真实部署必须按环境学习基线 / 本地重训——它直接论证了基线管理功能的必要性，比硬塞漂亮数字更有价值。
2. **换数据集 / 简单优化都会掉点**：UNSW 同分布 0.964，NSL 官方独立测试只有 0.797；且归一化对树模型无效、加高斯噪声增强反而降到 0.749，我没藏这些"优化失败"。
3. **规则引擎现代数据集召回 0.0001**：实证"固定规则跟不上现代攻击"，正是引入 ML 的理由。

# T — Think：诚实的局限、面试官会怎么挑、下一步

## T1. 项目边界（不吹成产品级防线）
它是**离线分析 / 安全管理辅助工具**，不替代在线防护；训练主要靠公开数据集，虽用跨数据集 + 真实样本补位，但数据集与生产的差距无法完全消除；"缺 WebView2 → 自动安装"分支还需在干净系统 / 虚拟机完整验证一次（本机已装、触发不了）。

## T2. 预判质疑与回应
- **"不就是调库？"** → 价值在选型依据、修掉"裸奔后端 / 重复报告 / 打包卡死"等工程问题、能解释每个指标口径；
- **"数字跑通就完了？"** → 跨域迁移、真实样本、RAG 对比，主动找反例、敢呈现失败；
- **"AI 是不是硬凑？"** → AI 定位清晰：不替引擎下结论，只解释、检索、研判、给处置建议，并用 RAG 真降低幻觉。

## T3. 下一步（按价值）
1. 干净系统验证安装全流程；
2. 建立**模型 / 基线持续更新与漂移监控**（跨域迁移实验已证明必要）；
3. 扩真实样本、提升少数类与时序召回；
4. 把"分析 → 运维反馈 → 重训"做成闭环，让助手从用户修正中学习——这也最贴合"研究方向继续深入"。

## T4. 回到初衷，达成了吗
- 对应**真实研究问题**（把安全分析能力下沉给一线运维）：✅；
- **轻量、可迁移、不拖垮机器**：✅（秒级、几十 MB、一键安装）；
- **经得起追问、数字可复现、失败也能解释**：✅；
- 它不是完美商业产品，但作为**源于硕士研究方向、有真实场景、可验证、讲得清"为什么"的工程级项目**，站得住。
