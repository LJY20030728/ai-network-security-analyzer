# 中间人攻击（Man-in-the-Middle Attack, MITM）

## 一、攻击定义与原理

中间人攻击（Man-in-the-Middle Attack，简称MITM）是一种间接的网络入侵攻击。攻击者通过各种技术手段，将自己控制的计算机放置在网络连接中的两台通信设备之间，秘密拦截、转发并可能篡改双方的通信数据，而通信双方却误以为他们在直接对话。

**核心原理**：攻击者在通信链路中插入一个"中间人"节点，所有通信数据都经过这个节点。攻击者可以窃听数据、修改数据、注入恶意内容，甚至完全控制通信会话。

**攻击条件**：攻击者需要能够访问通信双方之间的网络链路，或者能够欺骗通信双方将流量路由到攻击者控制的节点。

## 二、常见攻击类型

### 2.1 网络层MITM
1. **ARP欺骗（ARP Spoofing/Poisoning）**：最常见的局域网MITM技术，通过发送伪造的ARP响应包，欺骗目标设备将网关IP映射到攻击者的MAC地址，从而使流量经过攻击者
2. **DNS欺骗（DNS Spoofing）**：篡改DNS响应，将合法域名解析到攻击者控制的IP地址
3. **DHCP欺骗（DHCP Spoofing）**：部署恶意DHCP服务器，为客户端分配错误的网关和DNS服务器
4. **ICMP重定向**：发送伪造的ICMP重定向消息，欺骗主机修改路由表
5. **BGP劫持**：在互联网路由层面劫持IP前缀，使流量经过攻击者网络

### 2.2 应用层MITM
1. **SSL剥离（SSL Stripping）**：将HTTPS连接降级为HTTP连接，窃取明文数据
2. **SSL代理**：使用伪造的SSL证书，与客户端和服务器分别建立加密连接，中间解密数据
3. **会话劫持（Session Hijacking）**：窃取用户的会话Cookie，冒充用户身份
4. **Wi-Fi邪恶双子（Evil Twin）**：部署伪造的Wi-Fi热点，诱导用户连接后监控流量
5. **代理服务器MITM**：在代理服务器上拦截和修改流量

## 三、攻击流程（以ARP欺骗为例）

1. **扫描网络**：攻击者扫描局域网，发现目标主机和网关的IP/MAC地址
2. **发送伪造ARP响应**：攻击者向目标主机发送伪造的ARP响应，声称网关IP对应的MAC是攻击者的MAC
3. **同时欺骗网关**：向网关发送伪造的ARP响应，声称目标主机IP对应的MAC是攻击者的MAC
4. **流量转发**：攻击者开启IP转发，将目标主机的流量转发到真实网关，保持通信正常
5. **窃听/篡改**：所有流量经过攻击者，攻击者可以窃听敏感数据、修改数据包内容、注入恶意代码
6. **维持攻击**：持续发送伪造ARP包，防止ARP缓存过期恢复正常

## 四、网络流量检测特征

在PCAP流量分析中，中间人攻击通常表现为以下特征：

### 4.1 ARP欺骗特征
1. **重复ARP响应**：同一IP地址对应多个不同的MAC地址（`arp.duplicate-address-detected`）
2. **ARP风暴**：短时间内大量ARP请求和响应包
3. **网关MAC变化**：网关的MAC地址突然变为未知设备的MAC
4. **免费ARP异常**：大量免费ARP（Gratuitous ARP）包

### 4.2 SSL/TLS MITM特征
1. **证书异常**：TLS证书颁发者不是预期的CA，证书主题与域名不符
2. **证书指纹变化**：同一网站的证书指纹与历史记录不同
3. **降级攻击**：HTTPS连接被降级为HTTP
4. **弱加密套件**：协商使用已知不安全的加密套件
5. **异常TLS握手**：多次TLS握手失败或重新协商

### 4.3 其他特征
1. **异常路由**：数据包的TTL值与正常路径不同
2. **延迟增加**：通信延迟明显增加（因为多了一跳）
3. **数据篡改**：数据包内容被修改（校验和不匹配）
4. **DNS异常**：DNS响应的IP地址与权威DNS不一致
5. **未知设备**：网络中出现未知的MAC地址或设备

## 五、检测方法

1. **ARP监控**：监控ARP表变化，检测IP-MAC映射异常
2. **证书固定（Certificate Pinning）**：客户端固定服务器证书指纹，检测证书替换
3. **TLS证书监控**：监控网站证书变化，检测异常证书
4. **网络入侵检测系统（NIDS）**：部署Snort、Suricata等NIDS检测MITM特征
5. **DNS安全**：使用DNSSEC验证DNS响应真实性
6. **流量分析**：分析流量路径、延迟、TTL等特征
7. **端点检测**：在终端上检测ARP缓存异常、路由表变化
8. **Wi-Fi安全**：检测未知AP和邪恶双子攻击

## 六、防御措施

### 6.1 网络层防御
1. **动态ARP检测（DAI）**：在交换机上配置DAI，验证ARP包的合法性，丢弃伪造ARP
2. **DHCP Snooping**：在交换机上配置DHCP Snooping，建立IP-MAC绑定表，DAI基于此表验证
3. **静态ARP绑定**：在关键服务器和网关上静态绑定ARP条目
4. **802.1X认证**：部署802.1X网络接入认证，防止未授权设备接入
5. **网络分段**：将网络划分为多个VLAN，限制广播域范围
6. **VPN加密**：使用VPN加密所有网络通信，即使被拦截也无法解密

### 6.2 应用层防御
1. **HTTPS everywhere**：所有网站使用HTTPS，启用HSTS（HTTP Strict Transport Security）
2. **证书固定**：移动应用和关键客户端实现证书固定
3. **TLS 1.3**：使用最新的TLS 1.3协议，减少握手暴露
4. **安全DNS**：使用DNS over HTTPS（DoH）或DNS over TLS（DoT）
5. **端到端加密**：使用Signal、WhatsApp等端到端加密通信工具
6. **会话安全**：使用安全Cookie（HttpOnly、Secure、SameSite），定期轮换会话ID

### 6.3 管理防御
1. **安全意识培训**：培训用户识别不安全的Wi-Fi和可疑证书警告
2. **公共Wi-Fi谨慎使用**：不使用公共Wi-Fi进行敏感操作，必要时使用VPN
3. **证书警告重视**：浏览器出现证书警告时不要继续访问
4. **定期安全审计**：定期审计网络设备配置和安全状态
5. **零信任架构**：采用"永不信任，始终验证"的零信任安全模型

## 七、应急响应

1. **立即断网**：发现MITM攻击后立即断开受影响设备的网络连接
2. **定位攻击源**：通过ARP表、交换机MAC地址表定位攻击者设备
3. **清除ARP缓存**：清除受影响设备的ARP缓存，恢复正常通信
4. **凭据重置**：如果敏感信息可能被窃听，立即重置相关账户密码
5. **证书检查**：检查访问过的网站证书是否被替换
6. **恶意软件排查**：检查设备是否被安装了恶意代理软件
7. **网络加固**：在交换机上配置DAI和DHCP Snooping，防止再次发生
8. **事件报告**：向网络安全团队报告，配合调查
9. **改进防护**：根据事件教训加强网络安全防护
