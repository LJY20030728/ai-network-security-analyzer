- 技术栈：Python、FastAPI、Gradio、pywebview、Scapy、scikit-learn、ChromaDB、ONNX Runtime、SQLite、loguru

## 简历版本二（详细版，适合 2 页简历或技术岗）

**AI 辅助网络取证分析系统（AI Network Security Analyzer）**
独立项目 | 全栈开发 + 算法设计 | 2024.09 - 2026.09

**项目背景**：传统 PCAP 分析依赖人工逐包查看，效率低、经验依赖强；规则引擎对未知攻击漏报率高（UNSW-NB15 大流量类 Recall 仅 0.002）。本项目旨在构建一个 AI 辅助的离线取证工具，实现自动化检测 + 语义化研判 + 全流程闭环。

**核心工作与成果**：

1. **四引擎集成检测架构**（算法设计）
   - 设计策略模式 + 工厂模式的可扩展检测架构，支持动态插拔检测算法
   - 监督模型为主引擎（权重 0.5），规则/基线/孤立森林为辅（权重 0.2/0.15/0.15），加权集成投票
   - 实现 76 维 CICFlowMeter 风格双向流特征提取器（时间单位微秒），覆盖包长/时间/标志位/端口等维度
   - 监督模型 HistGradientBoosting 在 CIC-UNSW 447,915 流上训练，二分类 P=0.9351 R=0.9628 **F1=0.9487**
   - UNSW-NB15 域适应优化：194 维特征训练专用模型，**Recall=0.9769 F1=0.9700**，对比规则引擎 0.002 提升 4884 倍
   - 实现自适应阈值（基于输入流量 P95 分位数动态调整）+ 流级预测+PCAP 级聚合检测

2. **LLM 威胁研判 + 幻觉控制**（AI 工程）
   - 集成大模型 API（智谱/DeepSeek 兼容），将技术告警翻译为人类可读的威胁分析
   - 设计**幻觉控制三件套**：OutputValidator（格式/长度/合理性/与证据一致性/幻觉特征词检测）、ConfidenceCrossValidator（LLM vs 规则 vs 监督模型交叉验证，矛盾检测）、ReviewMarker（低置信度/矛盾结论自动标记"需人工复核"）
   - 实现 LLM 分析思考过程可视化 + 分析历史持久化

3. **RAG 安全知识问答**（检索增强生成）
   - 本地向量库 ChromaDB + BGE ONNX 推理（2768 条知识片段，零外部服务依赖）
   - 实现混合检索（BM25 关键词 + 向量语义）+ 轻量级重排序（标题 0.4 + 内容 0.3 + 元数据 0.2 + 向量距离 0.1 + 精确匹配加分）
   - 安全术语同义词扩展（10 类中文→英文），提升跨语言检索效果
   - 15 题黄金问答集评测：**Recall@5=0.36，严格召回率 66.7%，平均检索耗时 0.291s**

4. **时序基线 + STL 高级检测**（时序异常检测）
   - EWMA 时序基线引擎（学习-检测两阶段），中位数 + MAD 鲁棒尺度，4 维度联合检测（包数/字节/SYN/端口数），多维度同时偏差触发 CRITICAL 告警
   - 实现零依赖轻量级 STL 时序分解（趋势 + 季节性 + 残差），残差 z-score 异常检测，捕捉周期性偏离
   - KS 检验漂移检测，自动识别流量分布变化

5. **取证报告 + 知识库**（全流程闭环）
   - 取证报告五要素完整：事件时间线（严重度颜色标记）+ ATT&CK 攻击链 SVG 图（7 阶段杀伤链）+ IOC 失陷指标列表 + 证据链（告警→证据→引擎→时间窗口）+ 分析师备注
   - 历史记录升级为取证知识库：跨样本关联分析（相同攻击类型/相似告警/时间相近打分）+ 趋势分析（按日统计/攻击类型分布/严重度趋势）+ 重复检测缓存（SHA256 命中避免重复分析）+ IOC 提取

6. **工程化与安全**（工程深度）
   - FastAPI 后端 + Pydantic 集中管理 20+ 请求/响应模型，全局异常处理器（10+ 异常类型友好中文提示）
   - SQLite WAL 模式存储（历史记录/对话/基线三张表 + 索引），自动从旧 JSON 迁移
   - Windows DPAPI 加密存储 API Key（ctypes 调用 CryptProtectData，零额外依赖），绑定当前用户，图形化配置向导 + 有效性校验
   - 日志可观测性：日志查看器 API（级别/关键词过滤）+ 一键诊断报告（系统/Python/配置/数据库/最近错误/性能指标 7 大维度）
   - 141 个单元测试全绿，覆盖算法/API/存储/安全等模块
   - 性能基准：10 个黄金样本平均分析耗时 **5.911s/文件**，平均内存峰值 **22.97MB**

7. **历史记录报告管理与PCAP持久化**（用户体验与数据完整性）
   - 设计确认重新分析机制：报告文件被删除时显示确认区域询问用户，避免误操作，确认后分3阶段显示进度条（解析PCAP→生成报告→打开报告）
   - 后台独立执行架构：重新分析在后台独立线程执行完整PCAP分析（含AI研判），不影响主页面操作，支持多任务并行
   - PCAP文件自动持久化：分析完成后自动将PCAP文件复制到 `data/samples/analyzed/` 目录（时间戳前缀避免重名），确保重新分析时源文件一定存在，即使原始文件被删除
   - 旧记录兼容性处理：对于v2.0.0之前没有 `file_path` 字段的旧记录，自动在 `data/samples/`、桌面、下载目录搜索同名PCAP文件，搜索到后自动更新历史记录
   - 相同PCAP一一映射去重：使用基于PCAP文件SHA256的固定文件名，相同PCAP反复分析覆盖旧报告，避免报告目录堆积大量重复文件
   - 精确记录选择：下拉框精确选择历史记录（记录ID匹配），避免表格点击状态不同步导致打开错误报告
   - 修复严重Bug：Tab1/Tab2按钮变量名冲突导致点击打开两个报告、Gradio 6.x Dropdown不支持placeholder导致UI挂载404等

**技术栈**：

- 前端：Gradio 6、自定义 HTML/CSS、pywebview 桌面窗口
