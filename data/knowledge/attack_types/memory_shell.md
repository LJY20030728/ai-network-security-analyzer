# 内存马攻击（Memory Webshell / Memory Shell）

## 一、攻击定义与原理

内存马（Memory Webshell / Memory Shell）是一种无文件落地的Web后门技术，攻击者在获得一次代码执行能力（如反序列化漏洞、文件上传漏洞、RCE远程代码执行）之后，不向磁盘写入任何文件，而是通过反射、动态类加载、字节码操作等技术，在运行时向Web容器（如Tomcat、Spring、Jetty）或JVM中动态注入一个恶意组件（Filter、Servlet、Listener、Agent等），使容器在后续处理HTTP请求时自动执行攻击者的指令。

**核心原理**：利用Java等语言的动态特性，在运行时修改或注册Web容器的请求处理组件，将恶意逻辑植入内存中。由于不落地文件，传统的基于文件扫描的WebShell检测手段完全失效。

**三大杀手锏**：
1. **无文件落地**：不写入磁盘，传统文件监控无法检测
2. **进程级持久化**：只要Web容器进程不重启，内存马就一直存在
3. **高隐蔽性**：与正常Web组件混在一起，难以区分

## 二、常见内存马类型

### 2.1 按注入位置分类
1. **Filter型内存马**：动态注册恶意Filter，在请求处理前拦截并执行命令
2. **Servlet型内存马**：动态注册恶意Servlet，处理特定URL请求
3. **Listener型内存马**：动态注册恶意Listener，监听请求事件并执行命令
4. **Agent型内存马**：通过Java Agent机制注入，利用Instrumentation API修改类字节码
5. **Valve型内存马**：针对Tomcat的Valve管道机制注入
6. **Interceptor型内存马**：针对Spring MVC的拦截器机制注入

### 2.2 按实现技术分类
1. **反射型**：通过Java反射获取容器内部对象（如Tomcat的StandardContext），调用私有方法注册组件
2. **字节码操作型**：使用ASM、Javassist等库动态生成恶意类字节码
3. **动态类加载型**：通过ClassLoader.defineClass()加载恶意字节码
4. **Instrumentation型**：利用Java Agent的Instrumentation API重定义类

## 三、攻击流程

1. **获取初始执行能力**：利用反序列化、文件上传、RCE等漏洞获得一次代码执行
2. **获取容器上下文**：通过反射获取Web容器的Context对象（如Tomcat的StandardContext）
3. **构造恶意组件**：动态生成恶意Filter/Servlet/Listener类的字节码
4. **注册恶意组件**：调用容器API将恶意组件注册到容器中
5. **清理痕迹**：删除初始利用的文件，消除入侵痕迹
6. **持久化控制**：通过特定URL+参数访问内存马，执行任意命令

## 四、网络流量检测特征

在PCAP流量分析中，内存马攻击通常表现为以下特征：

1. **异常HTTP请求**：访问不存在的URL但带有特殊参数（如`?cmd=whoami`、`?pass=xxx`）
2. **请求参数异常**：参数名和值与正常业务逻辑不符，包含命令执行特征
3. **响应内容异常**：响应中包含系统命令执行结果（如`uid=0(root)`、目录列表等）
4. **无对应文件**：访问的URL在Web应用目录中没有对应的文件
5. **异常User-Agent**：使用冰蝎（Behinder）、哥斯拉（Godzilla）等WebShell管理工具的特征UA
6. **加密通信**：高级内存马使用加密通信，请求和响应内容不可读
7. **初始攻击流量**：反序列化漏洞利用、文件上传等初始入侵流量

## 五、检测方法

### 5.1 内存检测
1. **Java Agent检测**：使用Java Agent技术监控动态类加载和组件注册
2. **内存扫描**：扫描JVM内存中的类，查找异常类和恶意字节码
3. **组件枚举**：枚举Web容器中所有Filter/Servlet/Listener，与基线对比发现异常
4. **Arthas等诊断工具**：使用Java诊断工具查看运行时类和方法

### 5.2 流量检测
1. **异常请求检测**：监控访问不存在URL但带有命令参数的请求
2. **WebShell特征匹配**：匹配冰蝎、哥斯拉等工具的通信特征
3. **响应内容分析**：检测响应中的系统命令执行结果
4. **行为基线对比**：与正常业务请求基线对比，发现异常请求模式

### 5.3 主机检测
1. **进程内存分析**：分析Web容器进程的内存镜像
2. **系统调用监控**：监控异常的系统调用（如命令执行、文件操作）
3. **RASP（运行时应用自我保护）**：在应用运行时Hook关键方法，检测恶意调用

## 六、防御措施

### 6.1 阻断注入入口
1. **修复应用漏洞**：及时修复文件上传、反序列化、SpringEL注入等RCE漏洞
2. **输入验证**：对所有用户输入进行严格验证和过滤
3. **WAF防护**：部署WAF拦截已知攻击载荷
4. **最小权限**：Web应用进程以最低权限运行

### 6.2 限制容器权限
1. **关闭不必要端口**：关闭AJP 8009等不必要端口，避免类似CVE-2020-1938漏洞
2. **升级容器版本**：升级Tomcat等Web容器到最新版本
3. **启用Security Manager**：启用Java Security Manager，限制反射调用
4. **限制类加载**：监控和限制动态类加载行为

### 6.3 运行时防护
1. **部署RASP**：运行时应用自我保护，Hook关键方法检测恶意调用
2. **组件基线**：建立Web容器组件基线，定期对比发现异常注册
3. **内存马检测工具**：部署专门的内存马检测工具
4. **定期重启**：定期重启Web容器，清除内存中的恶意组件（但不能解决持久化问题）

### 6.4 网络防护
1. **流量监控**：监控异常HTTP请求和WebShell通信特征
2. **访问控制**：限制管理后台和敏感路径的访问IP
3. **HTTPS加密**：虽然不能阻止内存马，但可以防止流量被窃听
4. **日志审计**：完整记录Web访问日志，便于事后溯源

## 七、应急响应

1. **网络隔离**：发现内存马后立即隔离受感染服务器，防止横向移动
2. **内存取证**：使用内存取证工具保存进程内存镜像，用于分析
3. **清除内存马**：
   - 非Agent马：从容器中移除恶意组件（推荐），或访问时抛异常中断调用
   - Agent马：需要卸载Agent或重启JVM
4. **重启服务**：清除内存马后重启Web容器，确保内存中没有残留
5. **排查入口**：通过日志分析找到内存马的注入入口（漏洞利用点）
6. **修复漏洞**：修复被利用的安全漏洞，防止再次被注入
7. **持久化检查**：检查是否有计划任务、启动项等持久化机制
8. **横向移动排查**：检查内网其他服务器是否被入侵
9. **改进防护**：部署RASP和内存马检测工具，加强安全防护
