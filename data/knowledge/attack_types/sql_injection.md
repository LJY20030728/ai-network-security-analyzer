# SQL注入攻击（SQL Injection）

## 一、攻击定义与原理

SQL注入（SQL Injection，简称SQLi）是一种常见的Web安全漏洞，攻击者通过在应用程序的输入字段中插入恶意SQL代码，操控后端数据库查询，从而获取敏感数据、绕过认证机制甚至执行系统命令。

**核心原理**：当应用程序直接将用户输入拼接到SQL语句中时，攻击者输入的恶意SQL代码会被数据库当作正常SQL语句执行，本质是"数据被当作代码执行"。

## 二、常见攻击类型

1. **基于错误的注入**：通过构造错误SQL语句（如输入单引号），利用数据库返回的错误信息获取数据库结构信息
2. **基于联合查询的注入（UNION）**：使用UNION操作符将恶意查询结果与原始查询结果合并返回
3. **基于布尔的盲注**：通过构造布尔条件判断，根据页面返回差异逐字符猜解数据
4. **基于时间的盲注**：利用SLEEP()等函数，根据响应时间差异判断条件是否成立
5. **堆叠查询注入**：通过分号分隔执行多条SQL语句
6. **二阶注入**：恶意输入先存储在数据库中，后续被其他查询读取时触发注入

## 三、攻击危害

- **数据泄露**：获取用户密码、个人信息、商业机密等敏感数据
- **身份绕过**：绕过登录认证，以管理员身份登录系统
- **数据篡改**：修改或删除数据库中的数据
- **服务器控制**：通过写入WebShell或执行系统命令，完全控制服务器
- **拒绝服务**：通过大量查询导致数据库性能下降或崩溃

## 四、网络流量检测特征

在PCAP流量分析中，SQL注入攻击通常表现为以下特征：

1. **异常HTTP请求参数**：URL参数或POST数据中包含SQL关键字（SELECT、UNION、OR、AND、DROP等）
2. **特殊字符**：单引号（'）、双引号（"）、分号（;）、注释符（--、/* */）、括号等
3. **异常查询长度**：请求参数长度显著超过正常业务请求
4. **高频错误响应**：大量500错误或数据库错误页面
5. **可疑User-Agent**：SQLMap等自动化工具的特征User-Agent
6. **时间延迟**：基于时间的盲注会导致部分请求响应时间异常延长

## 五、检测方法

1. **WAF（Web应用防火墙）**：基于特征规则拦截SQL注入请求
2. **输入校验**：对用户输入进行白名单校验和类型检查
3. **异常流量分析**：监控HTTP请求中的SQL关键字和特殊字符
4. **数据库审计**：记录数据库执行的SQL语句，检测异常查询
5. **RASP（运行时应用自我保护）**：在应用运行时监控SQL语句构建过程

## 六、防御措施

### 6.1 最根本防御：参数化查询
- 使用Prepared Statements/预编译语句，将SQL语句结构与数据分离
- 用户输入严格作为参数处理，由数据库驱动自动转义
- 示例：`SELECT * FROM users WHERE username = ? AND password = ?`

### 6.2 输入验证
- 白名单优先：对数字、UUID、日期等强制类型验证
- 长度限制、字符集限制作为额外防线
- 不能替代参数化查询

### 6.3 最小权限原则
- Web应用数据库账户配置最小必要权限
- 杜绝使用root或sa等高级权限账户连接数据库
- 禁止FILE、PROCESS等危险权限

### 6.4 其他防御
- 部署WAF拦截已知攻击载荷
- 定期漏洞扫描和渗透测试
- 数据库错误信息不直接返回给用户
- 使用ORM框架的参数绑定功能
- 定期备份数据库，减少数据丢失风险

## 七、应急响应

1. **立即隔离**：发现SQL注入漏洞后，立即通过WAF拦截攻击IP
2. **漏洞修复**：使用参数化查询修复存在注入的代码
3. **数据排查**：检查数据库访问日志，确认是否有数据被窃取或篡改
4. **密码重置**：如果用户数据可能泄露，要求用户重置密码
5. **溯源分析**：通过Web日志和数据库审计日志追溯攻击来源和时间线
